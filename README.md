# haebeom.com

Personal academic homepage of Haebeom Jung. Static HTML generated by a small Python script from the LaTeX CV plus a few web-only data files. No framework, no Node build.

## How content flows

```
Overleaf ──sync──▶ github.com/zang09/CV_HaebeomJung  (content of record: cv/*.tex)
                              │
                              ▼  (checked out into cv-src/ by build.py or CI)
data/*.json + content/*.html ──▶ build.py ──▶ index.html, news/, publications/,
templates/base.html                            experience/, honors/, vitae/, sitemap.xml
                                            ──▶ assets/pdf/CV_HaebeomJung.pdf (compiled in CI)
```

| Source                      | Owns                                                                                                              |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `cv-src/cv/*.tex` (CV repo) | Education, experience, publications list, awards, patents, funding, service, skills, ongoing research             |
| `data/site.json`            | Hero: name, role, affiliation links, email, topics, social buttons, JSON-LD                                       |
| `data/news.json`            | News items (not in the CV)                                                                                        |
| `data/publications.json`    | Web extras per paper, matched by title substring: project/arXiv/code/DOI links, preview media, venue tags, BibTeX |
| `data/orgs.json`            | Per-organization logo, URL, one-line summary for the home timeline, note for Experience cards                     |
| `data/honors.json`          | Web extras per award, matched by substring: display title, awarder, summary, news link, `selected`                |
| `content/bio_*.html`        | Short and full bio paragraphs                                                                                     |
| `templates/base.html`       | Page shell: head, floating nav, footer                                                                            |

Commented-out entries in the `.tex` files (for example the POSTECH and UNIST internships) are ignored, so they appear neither in the PDF nor on the site. GPA bullets are dropped on the web (`hide_gpa` in `site.json`).

## Editing

- **CV content**: edit in Overleaf. Pushing to GitHub triggers a rebuild (see _Deploy_).
- **News**: add an object at the top of `data/news.json`. The home page shows the first 4.
- **New paper**: add it to `cv/publications.tex` in the CV, then add a matching object to `data/publications.json` and drop `name.jpg`, `name.mp4`, `name.webm` into `assets/img/papers/`. Papers whose venue contains "review" are listed on the Vitae page only.
- **New employer/school**: add it to the CV, then add its logo to `assets/img/logos/` and an entry to `data/orgs.json` (`flush: true` for tiles that already fill the square).
- **Honors**: add to `cv/awards.tex`; optionally add web extras in `data/honors.json`. `selected: true` shows it on the home page.
- **Design**: `assets/css/style.css`, `assets/js/main.js`, `templates/base.html`.

Then regenerate:

```bash
python3 build.py          # clones/updates cv-src/, regenerates pages, copies cv-src/cv.pdf if present
python3 build.py --pdf    # also compiles the PDF locally (needs TeX Live with the FontAwesome font available)
```

Open `index.html` directly in a browser or serve with `python3 -m http.server 8000`. Generated pages are committed so the repo works standalone; CI regenerates them anyway.

## Deploy

`.github/workflows/deploy.yml` runs on every push to `main`, daily at 03:00 UTC, on manual dispatch, and on a `cv-updated` repository dispatch. It checks out the CV repo, compiles `cv.pdf` with XeLaTeX, runs `build.py`, checks Prettier formatting of the hand-written sources, and publishes the tree to `gh-pages`. `CNAME` keeps the custom domain `www.haebeom.com`.

To make Overleaf pushes redeploy immediately, copy `.github/cv-repo/notify-site.yml` into the CV repository as `.github/workflows/notify-site.yml` and add a `SITE_DISPATCH_TOKEN` secret there (fine-grained PAT with Contents read/write on this repo). Without it, the daily schedule still picks up changes.

Before pushing, `npx prettier . --check` (also enforced by the `pre-push` hook; enable with `git config core.hooksPath .githooks`). Generated files are listed in `.prettierignore`.

The previous al-folio (Jekyll) version is preserved on the `al-folio-legacy` branch.
